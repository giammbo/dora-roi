# Code of conduct

## The short version

Be decent. Assume the person on the other side is trying to get something right.

## What is expected

This project exists because compiling a Register of Information by hand is miserable
work, and most people who show up here are doing it under a deadline set by a regulator.
That is a bad mood to arrive in, and it is not an excuse to take it out on anybody.

- **Argue with the claim, not the person.** "This marks a mapping guess as `FILLED`, and
  here is the case where that reaches a filing" is a good comment. "This is amateur hour"
  is not, and it also says less.
- **Say what you actually checked.** Especially about the domain: this is regulatory
  data, half of it is reconstructed, and a confident wrong answer costs somebody a
  rejected filing. "I read the annotated template, sheet B_02.02, row 15" beats "I'm
  pretty sure" every time.
- **Take the correction.** Being wrong in public about a field code is not a wound. Five
  of the fifteen templates in this repository were wrong until somebody checked.
- **Leave people's identity out of it.** Nationality, religion, gender, sexuality,
  disability, age, immigration status, appearance, employer, how good their English is.
  None of it has any bearing on whether a pull request is correct.

## What is not

Harassment, sexualised language or attention, insults, sustained disruption, doxxing,
publishing anyone's private information, or following someone here from another platform
to continue an argument. This applies in issues, pull requests, commits, code review and
anywhere else the project is being discussed.

Uploading production data — a real register, a real state file, real account
identifiers, a customer's name — into an issue or a pull request is not misconduct, but
it will be removed, and it is worth thinking about before you paste. If it has already
happened, say so and it will be handled quietly.

## Scope

Project spaces, and public spaces when you are representing the project.

## Enforcement

Report it to the maintainer, [@giammbo](https://github.com/giammbo), by direct message
or a private vulnerability report on this repository if you want a private thread and
have no other way to reach one. Reports are handled discreetly; the reporter's identity
is not disclosed to the person reported.

The maintainer may edit or remove content, ask for a change in behaviour, or block an
account, in proportion to what happened and whether it kept happening. Enforcement is one
person's judgement — there is no committee here, and pretending otherwise would be
theatre. If you think a decision was wrong, say so, once; you will get a real answer.
